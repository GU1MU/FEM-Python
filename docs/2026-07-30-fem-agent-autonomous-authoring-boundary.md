## 1. 目标

在现有 FEM GUI 中建立一条可审查、可取消、可恢复、revision 绑定的自主建模链：

```text
用户需求
  -> 需求缺项检查与确认
  -> Agent 私有草稿
  -> 类型化后端工具
  -> 结构化提案或可逆补丁
  -> GUI bridge
  -> ModelSession 原子应用
  -> 后台网格、预检和求解
  -> 有界结果查询
```

最终目标包括：

- 从空白 GUI 会话创建原生项目和部件；
- 从当前原生项目增加部件；
- 使用后端 recipe 和几何 API 建立几何；
- 使用显式网格尺寸或 AutoMesh 规则生成网格；
- 设置单元形状、阶次和局部加密；
- 建立稳定作用域；
- 定义材料、截面和截面分配；
- 定义线性静力分析步、边界条件、载荷和结果请求；
- 执行确定性模型预检；
- 在用户确认后提交求解；
- 从已接受的 GUI 求解结果执行有界查询和工程解释。

首个里程碑只要求支持现有内核能够完整验证和求解的二维偏心带孔平板线性静力
工作流。一般 CAD、任意分析类型和所有单元家族不作为首个里程碑的完成条件。

## 2. 与现有 Phase 编号的关系

现有 GUI Phase 1–6 属于 FEM Agent V0 GUI 接入系列。本文开启独立的
FEM Agent V1 Authoring 系列，使用 A0、A1、A2 等编号，避免与既有 Phase 6
CLI 退役工作混淆。

- V0 GUI Phase 5 负责现有 `.inp` Agent 能力进入 GUI；
- V0 GUI Phase 6 负责 GUI 对等后的 CLI 退役；
- V1 A0–A8 负责原生自主建模；
- V0 `.inp` 工作流与 V1 原生工作流可以共存；
- CLI 退役和 V1 A 系列不得在同一补丁中修改同一运行时、事件或工具边界。

V1 A1 可以在 V0 Phase 5 审查通过后开始。V0 Phase 6 是否先完成不改变本文边界，
但两个阶段必须使用独立计划、独立测试和独立提交。

## 3. 术语

### 3.1 绑定文档

绑定文档是一个 Agent session 明确关联的 GUI 文档。绑定至少包含：

- GUI document/session 标识；
- `source_kind`；
- `session_revision`；
- 当前模型名称；
- 当前原生部件标识；
- 当前可用能力摘要。

绑定关系只保存在本地。聊天框必须清楚显示当前绑定的模型或“未绑定模型”。

### 3.2 AuthoringContext

`AuthoringContext` 是从 GUI 当前 `ModelSession` 生成的只读、有界、类型化快照。
它可以包含：

- 文档和 revision 身份；
- 原生部件、几何 recipe 类型和维度；
- 网格意图与当前网格统计；
- 可用逻辑实体、内置区域和命名区域；
- 材料、截面、分配和分析步摘要；
- 当前验证、作业和结果状态；
- 支持的类型化操作及阻塞原因。

它不得包含完整节点数组、单元连接、结果数组、VTK 对象、Qt 对象或可变的
`ModelSession` 引用。

### 3.3 RequirementLedger

`RequirementLedger` 是 Agent 私有的结构化需求账本。每个工程字段至少记录：

- 字段类型和作用阶段；
- 当前值；
- 来源 turn；
- 状态：`missing`、`proposed`、`confirmed` 或 `invalidated`；
- 依赖项和失效原因。

账本不属于 GUI 工程模型，也不能直接授权模型修改。

### 3.4 RequirementReview

`RequirementReview` 是提交给用户审查的一组完整工程参数。用户在 GUI 中确认后，
对应字段才能从 `proposed` 进入 `confirmed`。

自然语言中的“可以”“就这样”等文字不能直接授权高风险操作。自然语言可以提供
参数和回答问题，最终工程参数仍通过有界审查卡确认。

### 3.5 AgentDraft

`AgentDraft` 是 Agent 私有数据根目录中的脱离状态，包含：

- 绑定文档身份和基准 revision；
- 已确认需求；
- 候选几何、网格意图和有限元定义；
- `draft_revision`；
- 本地验证结果；
- 待提交提案；
- 有界预览数据。

草稿独立于 `ModelSession`，也不拥有 GUI、VTK Actor 或当前结果。

### 3.6 ModelPatch

`ModelPatch` 是一个绑定精确 GUI revision 的类型化模型变更。它表达后状态或明确
操作，不包含任意 Python、Shell、回调、Qt 对象或原始后端对象。

### 3.7 AgentProposal

`AgentProposal` 是等待用户确认的结构化操作。几何提交、网格生成和求解提交均通过
提案进入 GUI。

### 3.8 AgentAuthoringBridge

`AgentAuthoringBridge` 是 Agent 工具和 GUI 公共命令之间的唯一写入边界。它负责：

- 在后台接收和验证 Agent 请求；
- 生成安全的 GUI 命令；
- 在 Qt 主线程应用同步命令；
- 通过现有任务控制器启动后台网格、预检或求解；
- 将命令回执、revision 和诊断返回 Agent；
- 拒绝陈旧、重复、越权或不可重放的请求。

## 4. 顶层不变量

自主建模的所有阶段必须保持以下不变量：

1. GUI `ModelSession` 是已接受工程模型的唯一事实来源。
2. AgentDraft 只保存候选状态，不能替代或覆盖 `ModelSession`。
3. Provider 不能持有 `ModelSession`、GUI command、Qt、VTK、Gmsh 或结果 Provider。
4. Agent 工具不能直接调用 `FEMMainWindow` 私有方法。
5. Agent 工具不能创建、删除或更新 VTK Actor。
6. 所有 GUI 写入必须经过 `AgentAuthoringBridge` 和公共 command/session 入口。
7. 所有写入绑定精确的 document/session 和 `session_revision`。
8. 陈旧提案拒绝执行，不能自动 rebase 或静默覆盖用户修改。
9. 高风险操作只能由 GUI 控件授权，Provider 工具调用和自然语言不能授权。
10. 后台失败不能留下半应用模型。
11. 网格和求解不能在 Qt 主线程执行。
12. 完整几何、网格和结果数组不能发送给 Provider。
13. 工程参数缺项时，工具必须确定性拒绝进入下一阶段。
14. Agent 创建的用户可见名称必须通过统一命名策略。
15. 每个已应用 Agent 变更必须能追溯到 Agent session、turn、tool call 和 patch。

## 5. 模型绑定边界

### 5.1 支持的绑定类型

V1 首轮只允许绑定：

- 空白 GUI 会话；
- 当前原生 `native` 项目。

导入的 `.inp` 文档继续使用 V0 检查、求解和结果查询工作流。V1 不把 imported
模型转换为可编辑 native 项目，也不向 imported 模型写入原生几何和定义。

### 5.2 空白会话

空白会话中，Agent 可以建立一个“创建原生项目并加入首个部件”的几何提案。
创建项目和安装首个部件必须作为一个应用事务：

- 全部验证成功后一次提交；
- 任一操作失败时保持空白会话；
- 用户只确认一次完整提案；
- 不允许先创建空项目再因第二步失败留下半完成状态。

### 5.3 已打开原生项目

已打开原生项目中，首轮只允许：

- 增加新部件；
- 为 Agent 本轮新增部件设置网格；
- 增加作用域和有限元定义；
- 对本轮目标模型进行预检、求解和结果查询。

删除现有部件、替换用户已有几何、合并用户已有部件、修改已有结果依赖的定义及
大范围重命名需要独立后续能力或显式高风险提案。

### 5.4 绑定失效

以下情况立即使绑定草稿和待确认提案失效：

- GUI 关闭或切换文档；
- `session_id` 改变；
- `session_revision` 与提案基准不一致；
- 当前项目从 native 变为 imported 或空白；
- 用户修改了提案依赖的部件、几何、网格、定义或分析步；
- 应用退出或 Agent session 被关闭。

失效后可以保留只读审计记录，但按钮必须禁用，Agent 需要重新读取
`AuthoringContext` 并重新生成提案。

## 6. 需求确认与禁止假设边界

### 6.1 工程参数分类

下列值属于工程参数，不能由 Agent 静默补充：

- 几何维度和建模假设；
- 单位上下文；
- 几何尺寸、位置、方向和数量；
- 材料参数；
- 截面类型和参数；
- 单元家族、阶次和网格密度；
- 局部加密位置和尺寸；
- 作用域语义；
- 分析过程；
- 约束自由度和数值；
- 载荷类型、方向、大小和分布；
- 结果请求；
- 任何会改变物理含义或数值结果的选项。

名称编号、内部 ID、事件 ID、proposal ID 和确定性排序属于操作元数据，可以由本地
代码生成。

### 6.2 建议值

Agent 可以提出建议值，但必须：

- 清楚标记为建议；
- 说明需要用户确认；
- 在 `RequirementReview` 通过前保持 `proposed`；
- 不调用依赖该值的建模、网格或求解工具。

### 6.3 阶段门

每个阶段都有独立的确定性前置条件：

| 阶段 | 至少需要确认的字段 |
| --- | --- |
| 几何 | 建模维度、单位、全部尺寸、孔或特征位置 |
| 网格 | 单元形状、阶次、显式尺寸或 AutoMesh level、局部加密 |
| 材料与截面 | 材料常数、截面类型、二维假设和厚度 |
| 分析 | 过程、约束、载荷、作用域和数值 |
| 求解 | 当前模型摘要、单位、验证结果和精确 revision |
| 结果 | 查询变量、分量、区域和聚合方式 |

缺少字段时，工具返回结构化 `clarification_required` 诊断。工具不能选择默认值后
继续执行。

### 6.4 单位上下文

原生项目需要增加应用层类型化单位上下文并随项目保存。至少表达：

- 长度；
- 力；
- 应力；
- 密度；
- 加速度；
- 可选约定名称。

单位上下文记录自洽约定，不自动转换已有数值。密度和加速度是否为当前分析必需，
由所选材料、体力和重力能力确定；未使用的字段可以保持明确的“不适用”，不能以
猜测值填充。

旧项目没有单位上下文时仍可打开。Agent 开始原生建模或求解前必须要求用户补充并
确认。

### 6.5 需求失效

修改上游需求会使依赖字段失效。例如：

- 改变二维/三维假设会使截面、单元和载荷作用域失效；
- 改变孔位置会使孔边局部加密和相关作用域失效；
- 改变单位会使材料、载荷、厚度和网格尺寸的确认状态失效；
- 改变单元家族会使截面、结果能力和局部控制失效；
- 改变载荷类型会使作用域和结果请求失效。

Agent 必须重新生成后续草稿和提案，不能保留已失效值继续工作。

## 7. 命名边界

### 7.1 格式

Agent 创建的用户可见名称必须满足：

```text
{type}-{function}
```

`type` 使用受控对象类型，首轮至少包括：

- `模型`
- `部件`
- `实体`
- `点`
- `边`
- `面`
- `域`
- `材料`
- `截面`
- `分析步`
- `位移`
- `载荷`
- `结果请求`
- `作业`

`function` 必须简短并表达工程作用，例如：

- `模型-偏心孔板`
- `部件-偏心孔板`
- `边-固定端`
- `边-加载端`
- `边-孔边`
- `域-板体`
- `材料-结构钢`
- `截面-平面应力`
- `分析步-静力`
- `位移-固定端`
- `载荷-拉伸`
- `结果请求-位移应力`
- `作业-静力1`

### 7.2 唯一性

统一 `NamePolicy` 和 `NameAllocator` 负责：

- Unicode 和大小写规范化后的冲突检查；
- 每个对象命名空间内的唯一性；
- 使用短数字后缀解决冲突；
- 拒绝空 function、首尾空白和过长名称；
- 拒绝冒充系统内置名称；
- 生成稳定、可重放的名称。

Provider 可以建议 function，最终名称由本地分配器生成。工具不能自行绕过
`NamePolicy`。

### 7.3 内部身份

现有 `LEFT`、`RIGHT`、`HOLE`、`DOMAIN` 等内置区域可以继续作为内部技术标识。
用户可见作用域使用符合命名规范的别名。显示名称不能替代稳定的 part ID、逻辑
实体 ID、mesh entity identity 或 result source identity。

### 7.4 当前数据结构缺口

当前位移边界条件和载荷记录没有独立用户名称。进入 A5 前必须增加应用层名称契约，
并覆盖：

- 位移边界条件；
- 节点载荷；
- 边载荷；
- 面载荷；
- 线载荷；
- 体力和重力；
- 项目序列化与迁移；
- GUI 列表、编辑和删除身份；
- Agent 摘要和审计。

旧项目中的匿名对象需要确定性的兼容显示名；只有 Agent 新建对象强制执行本文
命名规范。

## 8. AgentDraft 边界

### 8.1 存储

AgentDraft 保存在 Agent 私有数据根目录，不写入用户工作区或 `.femproj`。

只有用户已接受并进入 `ModelSession` 的状态才属于工程项目。待确认草稿、被拒绝
提案和中间工具产物不会随项目保存。

### 8.2 Revision

草稿同时记录：

- `base_document_id`
- `base_session_id`
- `base_session_revision`
- `draft_revision`
- 已确认需求摘要 hash
- 候选模型 hash

每次草稿写入递增 `draft_revision`。任意上游变更使依赖提案失效。

### 8.3 能力

草稿允许：

- 构造和验证后端 recipe；
- 计算纯几何摘要；
- 生成有界静态预览；
- 建立网格意图；
- 建立作用域和定义候选；
- 运行脱离状态验证；
- 生成 ModelPatch 或 AgentProposal。

草稿禁止：

- 修改 GUI document；
- 调用主窗口投影；
- 复用 GUI VTK Actor；
- 把完整 Gmsh model 或 FEMModel 持久化为 Provider 上下文；
- 将草稿伪装成已接受模型；
- 在未确认需求上执行依赖工具。

## 9. 几何建模边界

### 9.1 Agent 工具层

Agent 几何工具使用现有类型化 recipe 和 application API。首轮优先覆盖：

- 矩形；
- 圆盘；
- 偏心带孔平板；
- 长方体；
- 圆柱；
- 平移和旋转；
- 受支持的拉伸；
- 已有可证明 lineage 的布尔操作。

工具参数使用工程语义，不暴露 Gmsh tag、原始 OCC handle、任意脚本或任意
`gmsh.option`。

### 9.2 稳定引用

Agent 只能使用：

- part ID；
- `LogicalEntityRef`；
- 内置区域；
- 类型化持久选择规则；
- 已生成网格中的 `MeshEntityRef`。

原始 Gmsh entity tag 和会话内 `EntityRef` 不能进入持久草稿、Provider 上下文或
ModelPatch。

### 9.3 GUI 刷新

Agent 在草稿中建立、修改和验证几何时：

- GUI `ModelSession` 不变；
- 模型树不刷新；
- VTK Actor 不变；
- 相机和选择不变；
- `session_revision` 不变。

可以在聊天卡片中显示本地生成的有界静态预览。该预览不进入模型视口，也不代表
几何已经加入项目。

### 9.4 几何提案

几何完成后生成独立提案，至少显示：

- 目标模型和操作类型；
- 新项目或增加部件；
- 部件名称；
- recipe 类型和维度；
- 关键尺寸和单位；
- 孔、切除或变换参数；
- 预计新增和失效对象；
- 基准 GUI revision；
- proposal hash。

用户点击“加入模型”后，GUI bridge 在主线程原子应用。成功后只刷新一次完整投影。

### 9.5 首轮修改范围

A2 首轮只实现创建项目和增加部件。以下操作留到首个端到端里程碑之后：

- 删除用户已有部件；
- 替换已有部件几何；
- 跨用户已有部件的布尔合并；
- 自动修复未知拓扑；
- 通过图像反推精确 CAD；
- 执行任意用户脚本。

## 10. 网格边界

### 10.1 MeshIntent

应用层需要一个统一、可持久化的网格意图，至少支持：

1. 显式模式：全局尺寸、阶次、严格单元形状和局部控制；
2. 自动模式：AutoMesh level、阶次、严格单元形状和局部控制。

显式模式和自动模式不能在同一部件上同时生效。工具必须明确报告当前模式。

### 10.2 单元和局部加密

首轮覆盖：

- 二维三角形或四边形；
- 一阶或当前内核支持的二阶单元；
- 全局尺寸或 AutoMesh level；
- 基于稳定几何引用的局部尺寸；
- 孔边局部加密；
- 类型化 falloff。

Agent 不能选择内核未支持的单元，不能在严格形状失败后静默降级，也不能自动改用
另一网格算法。

### 10.3 网格提案

开始 Gmsh 前必须显示确认卡，至少包含：

- 目标模型和部件；
- 全局尺寸或 AutoMesh level；
- 单元形状和阶次；
- 局部加密目标和尺寸；
- 已知资源等级或有界估计；
- 会失效的网格、作用域、定义、验证和结果；
- 基准 revision 和 proposal hash。

单元数量估计只能作为估计展示，不能伪装为生成结果。

### 10.4 原子生成

用户确认后：

1. GUI bridge 从已确认提案构造脱离的网格任务；
2. Gmsh 在后台执行；
3. GUI 当前网格在计算期间保持不变；
4. 生成结果完成后再次检查 document/session/revision；
5. 完全匹配时一次提交网格意图和生成模型；
6. 陈旧或失败结果被丢弃，GUI 模型保持原状；
7. AgentDraft 保留网格意图，便于用户修改后重新提案。

现有 GUI 在重新划分前清除旧模型的行为不能直接用于 Agent 原子网格提案。A3 需要
新增“生成成功后替换”的 application command/session 事务。

### 10.5 Gmsh 资源

Gmsh 具有进程级状态。所有 GUI 与 Agent 几何编译、预览和网格任务必须经过统一的
进程级执行协调器：

- 同一时刻只允许一个 Gmsh 所有者；
- 不依赖 GUI task busy 状态间接实现互斥；
- 取消、失败和异常后恢复 Gmsh 状态；
- 不让一个 Agent session 阻塞后续 session 的关闭；
- 长时间任务保持可取消和有界。

## 11. 作用域边界

### 11.1 作用域来源

Agent 可以通过以下来源建立作用域：

- recipe 内置语义区域；
- `LogicalEntityRef`；
- 可证明的类型化几何选择规则；
- 已生成网格的 `MeshEntityRef`；
- 整个 domain。

类型化选择规则至少表达目标实体种类、空间条件、容差和预期数量。规则执行后返回
有界证据，例如匹配数量、边界框和语义摘要。

### 11.2 Fail closed

出现以下情况时拒绝建立作用域：

- 拓扑 lineage 不精确；
- 选择结果为空；
- 选择数量与预期不符；
- 同一作用域混合不兼容实体种类；
- 选择依赖临时 Gmsh tag；
- 当前 revision 已变化；
- 无法证明选择结果仍对应用户描述。

Agent 需要继续追问或请求用户在 GUI 中选择，不能选择“最接近”的未知实体继续。

### 11.3 自动应用

在已接受几何和本轮明确建模目标内，新增作用域可以自动应用，无需单独确认。

自动应用必须：

- 使用精确 revision；
- 只执行新增或非破坏性替换；
- 显示“Agent 已创建……”事件；
- 记录 ModelPatch；
- 提供“撤销本次 Agent 修改”；
- 不主动改变相机或当前选择；
- 根据 `SessionDelta` 执行最小必要投影。

删除、覆盖用户已有同名作用域、级联修改已有定义或使已接受结果失效时，需要显式
确认。

## 12. 材料、截面和定义边界

### 12.1 材料与截面

Agent 可以在已确认需求上建立：

- 线弹性材料；
- 当前内核支持的密度；
- 实体、平面、梁和杆截面；
- 截面参数；
- 截面到作用域的分配。

材料常数、厚度、面积、惯性矩和方向均属于工程参数。Agent 不能从材料名称推断
数值，也不能使用未由用户选择的数据源。

### 12.2 定义批次

同一逻辑步骤中的材料、截面和分配应作为一个原子定义批次：

- detached 状态先验证；
- 名称和引用先解析；
- 全部通过后一次应用；
- 任一失败不改变 GUI 模型；
- 变更后返回新 revision 和失效项。

### 12.3 自动应用和结果失效

在尚无已接受求解结果的自主建模工作流中，新增材料、截面和分配可以自动应用。

如果当前项目已有有效结果，任何会使网格、模型、验证或结果失效的定义修改都需要
显式确认，并在卡片中列出失效影响。

## 13. 分析步、边界条件和载荷边界

### 13.1 首轮过程

首个里程碑只支持：

- 一个线性静力分析步；
- `NLGEOM` 关闭；
- 当前内核已经支持的位移边界条件；
- 节点、二维边或三维面的受支持载荷；
- 当前内核已经支持的输出请求。

动力、非线性、接触、热、耦合、多步历史和优化属于后续独立能力。

### 13.2 前置条件

建立边界条件或载荷前必须确认：

- 目标作用域；
- 目标实体类型；
- 自由度或载荷类型；
- 分量、方向和符号；
- 数值与单位；
- 分布方式；
- 所属分析步。

“固定左端”“右端加载”等语义需要解析为确定的作用域和自由度摘要，再由用户确认
工程含义。工具不能把“固定”自动扩展为未知维度下的全部自由度。

### 13.3 自动应用

在本轮新建分析、无有效旧结果且需求已确认时，分析步、边界条件、载荷和输出请求
可以自动应用。每次应用需要显示对象名称、目标、数值、单位和新 revision。

覆盖已有同名对象、删除对象、改变已有分析过程或使有效结果失效时需要显式确认。

## 14. 预检、求解和结果边界

### 14.1 预检

确定性模型预检属于只读计算，无需求解确认。Agent 可以自动执行：

- 模型能力检查；
- 材料与截面完整性检查；
- 作用域引用检查；
- 约束和载荷检查；
- 刚体运动和数值稳定性检查；
- 结果请求能力检查；
- 有界网格统计和质量检查。

预检失败时不能进入求解提案。

### 14.2 求解提案

求解提案至少绑定：

- GUI document/session；
- `session_revision` 和 model revision；
- validation stamp；
- 分析步；
- 作业名称；
- 网格规模和单元类型；
- 材料、截面、约束和载荷摘要；
- 单位上下文；
- 阻塞诊断；
- proposal hash。

用户点击“开始求解”后才能提交作业。自然语言、Provider 工具调用、旧事件和重放
日志不能授权。

### 14.3 求解执行

求解继续使用现有 GUI task/session 入口：

- 后台执行；
- 支持合作取消；
- 结果绑定精确 artifact/model revision；
- 陈旧结果不能覆盖当前模型；
- 失败、取消和成功均产生结构化终态；
- 结果是否自动切换到视口显示遵守现有 GUI 作业行为。

### 14.4 结果查询

Agent 通过 GUI 原生 `ResultProvider` 和类型化结果目录查询已接受结果。

允许返回 Provider 的内容：

- 有界标量；
- 最大值、最小值、绝对值极值和合计；
- 节点、单元或区域身份；
- 单位；
- run、step 和 result source 摘要；
- 有界诊断。

禁止发送给 Provider：

- 完整位移、反力或应力数组；
- 完整节点坐标；
- 完整单元连接；
- VTK 数据；
- 任意本地绝对路径；
- 未经本地计算的估计结果。

Agent 的只读结果查询不得自动改变当前视口字段、分量、相机、选择或变形比例。
用户明确要求“显示”某结果时，另行通过类型化 GUI 显示命令处理。

## 15. 确认与权限矩阵

| 操作 | 默认策略 | 说明 |
| --- | --- | --- |
| 读取 AuthoringContext | 自动 | 只读、有界 |
| 记录和更新需求草稿 | 自动 | 不写 GUI 模型 |
| 确认 RequirementReview | 用户确认 | 工程参数进入 confirmed |
| 构造和验证 AgentDraft | 自动 | 不写 GUI 模型 |
| 创建原生项目并加入首个部件 | 用户确认 | 原子几何提案 |
| 向原生项目增加部件 | 用户确认 | 原子几何提案 |
| 开始划分网格 | 用户确认 | 后台高成本操作 |
| 新增作用域 | 自动、可撤销 | 无旧结果且无覆盖 |
| 新增材料、截面和分配 | 自动、可撤销 | 需求已确认且无旧结果 |
| 新增分析步、边界和载荷 | 自动、可撤销 | 需求已确认且无旧结果 |
| 删除、覆盖、级联重命名 | 用户确认 | 列出影响 |
| 使现有网格或结果失效 | 用户确认 | 列出失效项 |
| 模型预检 | 自动 | 只读计算 |
| 提交求解 | 用户确认 | 精确 revision/hash |
| 查询已接受结果 | 自动 | 只读、有界 |
| 导出或写入用户工作区 | 用户确认 | 明确目标文件 |

GUI 确认按钮是唯一授权入口。Agent 工具目录中不得注册
`accept_proposal`、`confirm_mesh` 或 `confirm_solve` 等 Provider 可调用工具。

## 16. ModelPatch 和 AgentProposal 契约

### 16.1 必需字段

每个 patch 或 proposal 至少包含：

- `schema_version`
- `patch_id` 或 `proposal_id`
- `agent_session_id`
- `turn_id`
- `source_tool_call_ids`
- `target_document_id`
- `target_session_id`
- `base_session_revision`
- `draft_revision`
- 类型化 operations
- 前置条件
- 预期变更
- 失效影响
- 安全展示摘要
- idempotency key
- 完整 hash

### 16.2 操作

operations 使用封闭的 discriminated union，例如：

- 创建 native project；
- 增加 native part；
- 设置 part mesh intent；
- 增加或替换 named region 后状态；
- 增加或替换 model definitions 后状态；
- 请求网格任务；
- 请求预检；
- 请求求解；
- 请求结果查询。

未知操作、未知字段和任意可执行文本均拒绝。

### 16.3 原子性

一个 patch 的全部 operations：

- 在 detached 状态验证；
- 在一个 revision 门下应用；
- 成功时只产生一个接受终点；
- 失败时不改变模型；
- 返回精确的新 revision；
- 不依赖异常后的补偿性 GUI 操作恢复状态。

### 16.4 可逆性

自动应用的 patch 必须提供受控撤销能力。首轮可以使用“精确后状态 + 精确前状态”
生成一次性 inverse patch：

- 只在当前 revision 仍与 Agent patch 后状态匹配时允许撤销；
- 用户后续修改后，旧撤销入口变为陈旧；
- 撤销同样经过公共 command/session；
- 撤销记录不等同于现有几何特征 undo。

在通用 GUI undo/redo 栈建立前，不得声称所有 Agent 编辑已经进入全局撤销历史。

### 16.5 生命周期

proposal 状态至少包括：

- `draft`
- `pending_confirmation`
- `accepted`
- `rejected`
- `stale`
- `running`
- `succeeded`
- `failed`
- `cancelled`

每个 proposal 只能进入一次授权终态。重复点击、事件重放和跨 session 使用均拒绝。

## 17. GUI 事件和展示边界

现有 schema `1.0` 的 `confirmation_requested` 继续服务 V0 求解确认。

V1 需要新增类型化 proposal 事件，至少表达：

- proposal 请求；
- 用户接受；
- 用户拒绝；
- 陈旧；
- 后台开始；
- 进度；
- 成功；
- 失败；
- 取消。

事件 schema 采用显式新版本或新增严格事件类型，不能向 schema `1.0` payload
静默增加未知字段。

提案卡片不得展示原始 ModelPatch。GUI 只展示本地生成的有界摘要、影响和确认按钮。
Provider 提供的自然语言不能成为确认卡的唯一摘要来源。

## 18. GUI 投影与刷新边界

### 18.1 草稿期间

需求追问、草稿建模、草稿验证和提案生成期间：

- GUI document 不变；
- 模型树和属性面板不刷新；
- VTK 场景不刷新；
- 视口不 fit；
- 相机和选择不变。

### 18.2 模型写入

成功应用 patch 后，GUI 根据 `SessionDelta` 执行投影：

- 几何提交：一次完整模型投影；
- 作用域和定义：最小必要树和符号更新；
- 网格成功：一次完整网格和模型投影；
- 预检：只更新验证和状态；
- 求解成功：按现有结果工作流安装结果；
- 结果查询：不改变视口。

### 18.3 失败

任何失败、取消或陈旧结果：

- 不投影候选模型；
- 不创建临时 Actor；
- 不改变相机；
- 不把部分工具结果写入模型树；
- 只显示结构化诊断和可重试入口。

## 19. 线程、任务和资源边界

### 19.1 Qt 主线程

Qt 主线程只执行：

- Qt 控件更新；
- GUI 公共同步 command；
- `SessionDelta` 投影；
- 后台任务的开始与接受回调；
- 用户确认控件处理。

### 19.2 后台执行

后台执行：

- Provider；
- Agent engine 和工具循环；
- AgentDraft 验证；
- Gmsh；
- 网格质量检查；
- FEM 预检；
- 求解；
- 结果物化和有界聚合；
- 项目文件 IO。

### 19.3 串行关系

- 同一个 Agent session 的工具保持串行；
- 同一个绑定文档的写 patch 保持串行；
- Gmsh 任务全进程串行；
- GUI 现有模型任务与 Agent 模型任务通过同一个协调器仲裁；
- 只读结果查询可以在结果 source 和 materialization generation 精确绑定时执行；
- 应用退出时先取消，再等待有界关闭。

## 20. Agent 工具边界

### 20.1 工具分层

工具按能力分为：

1. 上下文工具：读取绑定、能力、需求缺项和模型摘要；
2. 草稿工具：建立候选几何、网格意图、作用域和定义；
3. 验证工具：执行纯验证、预检和资源检查；
4. 提案工具：请求 GUI 显示待确认提案；
5. 查询工具：读取已接受模型和结果的有界信息。

工具目录应按当前阶段动态发布，减少 Provider 在错误阶段调用无效工具。

### 20.2 不允许的工具

V1 不提供：

- 任意 Python；
- Shell；
- 任意文件路径读取；
- 任意 Gmsh option；
- 原始 OCC/Gmsh tag；
- 原始节点或单元数组；
- 直接 GUI click 或控件操作；
- 直接 ModelSession 写入；
- Provider 可调用的确认工具；
- 绕过 NamePolicy 的写入工具；
- 自动安装依赖或修改 Provider 配置的工具。

### 20.3 工具实现位置

FEM 后端能力继续位于 `fem` 和 `fem.application`。Agent tool handler 只负责：

- schema 校验；
- 权限和阶段门；
- 调用后端服务；
- 结果裁剪；
- 诊断归一化；
- 审计。

GUI 不复制几何、网格、材料或求解算法。`fem_agent` 也不导入 `fem_gui`。
跨层依赖通过协议接口和不可变 DTO 完成。

## 21. 数据与隐私边界

### 21.1 可以发送给 Provider

- 用户聊天文字；
- 已明确引用的有界文件上下文；
- AuthoringContext 的有界工程摘要；
- 已确认需求；
- 名称和数量；
- 材料、几何、网格、载荷和边界的有界参数；
- 本地诊断；
- 有界结果标量。

### 21.2 保持本地

- 完整几何后端状态；
- Gmsh model；
- 完整节点和单元；
- 完整结果数组；
- VTK 数据；
- GUI 对象；
- ModelPatch 原始前后快照；
- 绝对路径；
- Agent 私有数据路径；
- API Key 和凭据。

工程参数和对象名称可能包含业务信息。聊天框在绑定模型时必须明确提示当前模型摘要
可能进入 Provider 上下文，并继续遵守现有 Provider 隐私说明。

## 22. 失败、取消与恢复边界

### 22.1 工具失败

工具失败返回：

- 稳定错误码；
- 阶段；
- 有界消息；
- 是否可重试；
- 是否需要用户澄清；
- 是否使草稿或提案失效。

失败不能触发隐藏 fallback 或扩大权限。

### 22.2 用户拒绝

用户拒绝提案后：

- GUI 模型保持不变；
- proposal 进入 `rejected`；
- AgentDraft 可以保留；
- Agent 可以根据用户后续要求修改草稿；
- 同一 proposal 不能再次授权。

### 22.3 取消

- 取消 Provider turn 不自动撤销已接受 patch；
- 取消网格或求解保留已接受的上游模型；
- 取消后不应用晚到结果；
- 关闭聊天抽屉不取消；
- 关闭绑定文档使待执行提案陈旧；
- 应用退出执行有界 cooperative shutdown。

### 22.4 恢复

重启应用后：

- 已进入 `.femproj` 的模型状态按项目恢复；
- Agent 私有会话可以恢复对话和只读审计；
- 未执行提案默认视为陈旧；
- 恢复提案必须重新绑定当前 document/session/revision 并重新确认；
- 运行中的 Gmsh 或求解任务不伪装成仍在运行。

## 23. 首个里程碑工作流

首个验收提示词：

```text
帮我建立一个偏心的带孔平板模型，孔的位置偏离板的中心
```

预期流程：

1. Agent 识别几何、网格、材料、边界和载荷参数不完整。
2. Agent 先确认二维平面应力、二维平面应变或三维实体。
3. Agent 询问单位、板尺寸、厚度、孔径和孔心坐标或中心偏移。
4. Agent 询问材料、约束、载荷和结果目标。
5. Agent 询问单元形状、阶次、网格尺寸和孔边加密。
6. GUI 显示完整 `RequirementReview`，用户确认全部工程参数。
7. Agent 在私有草稿中建立 `模型-偏心孔板` 和 `部件-偏心孔板`。
8. GUI 显示几何提案；用户点击“加入模型”。
9. GUI 一次性显示几何。
10. Agent 建立网格意图和 `边-孔边` 局部加密。
11. GUI 显示网格提案；用户点击“开始划分”。
12. 网格后台完成后一次性进入 GUI。
13. Agent 自动建立 `边-固定端`、`边-加载端`、`域-板体`。
14. Agent 自动建立材料、截面、分析步、位移、载荷和结果请求。
15. Agent 自动执行模型预检。
16. GUI 显示精确 revision 绑定的求解摘要；用户点击“开始求解”。
17. 求解成功后 Agent 查询最大位移、应力极值、位置和支反力。
18. Agent 只使用确定性工具结果回答，不估算数值。

任一阶段修改上游参数时，后续依赖状态失效并回到相应确认点。

## 24. Authoring Phase 路线

### A0：自主建模边界确定

目标：

- 审查并锁定本文；
- 确定确认矩阵、命名规则、模型绑定和首个里程碑；
- 不修改产品代码。

验收：

1. 用户确认本文边界。
2. 后续每个阶段均有独立计划、实现、测试和审查。
3. V0 GUI 边界继续有效。

### A1：模型绑定、需求账本、草稿、提案和 bridge 骨架

目标：

- 建立 `AuthoringContext`；
- 建立本地模型绑定；
- 建立 `RequirementLedger` 和 `RequirementReview`；
- 建立 `AgentDraft` 身份和 revision；
- 建立 ModelPatch/AgentProposal DTO、hash 和 idempotency；
- 扩展 proposal 事件和 GUI 卡片；
- 建立 Fake AuthoringPort 和 `AgentAuthoringBridge`；
- 不修改真实 `ModelSession`。

允许：

- 读取有界的当前 native 模型摘要；
- 显示绑定状态；
- 使用 Fake Provider 生成需求缺项和静态提案；
- 接受、拒绝和陈旧化无副作用提案；
- 测试事件重放和按钮授权。

禁止：

- 真实几何写入；
- 真实网格；
- 真实定义写入；
- 真实求解；
- Provider 调用 GUI 确认。

验收：

1. 切换文档后旧提案立即陈旧。
2. 自然语言和工具调用不能授权。
3. RequirementReview 未确认时建模阶段门拒绝。
4. AuthoringContext 不含完整数组、绝对路径或 GUI 对象。
5. proposal 事件可严格重放。
6. GUI 主线程不执行 Provider 或 Agent 工具。

### A2：单位、命名与几何草稿/提交

目标：

- 增加原生项目单位上下文；
- 建立 `NamePolicy` 和 `NameAllocator`；
- 接入首批 recipe 几何工具；
- 支持空白会话原子创建项目与首个部件；
- 支持向 native 项目增加部件；
- 实现几何静态预览、提案和一次性 GUI 刷新。

首批必须支持：

- `PlateWithHoleGeometry`；
- 矩形和圆盘；
- 长方体和圆柱；
- 必要的平移或旋转。

验收：

1. 偏心孔参数可以由明确孔心坐标或中心偏移表达。
2. 孔必须完整位于板内，失败时 GUI 不变。
3. 确认前 GUI revision、模型树和 Actor 不变。
4. 用户拒绝后 GUI 不变。
5. 用户接受后只增加一个符合命名规则的部件。
6. 空白项目创建和首部件安装保持原子。
7. 陈旧几何提案不能提交。
8. 项目保存和重开保留单位及已接受几何。

### A3：网格意图、局部加密和确认生成

目标：

- 建立显式/自动 `MeshIntent`；
- 接入 `MeshSettings` 和 `AutoMeshSpec`；
- 接入单元形状、阶次、全局密度和局部加密工具；
- 建立 Gmsh 全局执行协调器；
- 实现网格确认和成功后原子替换。

验收：

1. 未点击“开始划分”时不调用 Gmsh。
2. 显式尺寸和 AutoMesh level 不能混用。
3. 孔边局部加密使用稳定逻辑引用。
4. 严格单元形状失败时不降级。
5. 网格运行期间当前 GUI 模型保持不变。
6. 失败、取消或陈旧结果不清除旧网格。
7. 成功后网格意图和模型一次提交、一次刷新。
8. 同一时刻只有一个 Gmsh 所有者。

### A4：作用域、材料、截面和分配

目标：

- 接入内置区域、逻辑实体和网格实体作用域工具；
- 建立用户可见语义别名；
- 接入材料、截面和分配工具；
- 建立自动 ModelPatch 和一次性 inverse patch；
- 支持无确认的可逆中间编辑。

验收：

1. 偏心孔板可稳定得到固定端、加载端、孔边和板体作用域。
2. 作用域名称遵守命名规则。
3. 不精确拓扑或选择数量异常时 fail closed。
4. 材料、截面和分配作为原子批次应用。
5. 自动编辑显示摘要和撤销入口。
6. 当前 revision 改变后旧撤销入口禁用。
7. 修改会使已有结果失效时转为确认提案。
8. 项目保存和重开保留全部定义。

### A5：分析步、命名边界条件、载荷和结果请求

目标：

- 增加边界条件和载荷的稳定名称；
- 完成项目 schema 迁移和 GUI 编辑身份；
- 接入一个线性静力步；
- 接入当前内核支持的位移、节点/边/面载荷；
- 接入结果请求；
- 继续使用可逆自动 patch。

验收：

1. 每个位移和载荷都有唯一、符合规范的名称。
2. Agent 不能从“固定”推断未知维度下的自由度。
3. 载荷方向、大小、符号、作用域和单位都经过确认。
4. 匿名旧项目可兼容打开。
5. 分析定义失败时 GUI 后状态不变。
6. 一个步骤的定义可以完整保存、重开和重新编译。
7. 首个里程碑模型具备完整、可预检的静力分析定义。

### A6：确定性预检、求解摘要和 GUI 求解确认

目标：

- 自动执行模型预检；
- 生成绑定 GUI revision 和 validation stamp 的确定性摘要；
- 泛化确认卡用于 native 求解；
- 使用现有 GUI job/session 后台求解；
- 映射进度、取消、成功和失败。

验收：

1. 阻塞诊断存在时不能生成可执行求解提案。
2. 自然语言和 Provider 工具不能授权求解。
3. revision 或 validation stamp 变化后按钮禁用。
4. 用户点击后只提交一次作业。
5. 求解不在 Qt 主线程执行。
6. 取消和晚到结果不能覆盖当前模型。
7. 求解成功结果绑定精确 artifact、run 和 model revision。

### A7：原生结果目录、有界查询和 Agent 解释

目标：

- 把 GUI `ResultProvider` 和结果目录接入 Agent 查询工具；
- 支持位移、反力和应力的有界查询；
- 支持区域极值、位置和反力合计；
- 保持完整结果数组本地；
- 让 Agent 基于工具返回进行简洁工程解释。

验收：

1. Agent 不能在无结果时回答数值。
2. 查询绑定精确 result source 和 materialization generation。
3. Provider 只收到有界标量和身份摘要。
4. 结果查询不改变视口字段、相机或选择。
5. 陈旧结果 source 被拒绝。
6. 最大位移、应力极值和固定端反力可以从首个里程碑模型读取。
7. 单位和位置随每个标量返回。

### A8：偏心带孔平板端到端验收与加固

目标：

- 使用目标自然语言提示完成全链路；
- 增加 Fake Provider 确定性端到端测试；
- 增加可选真实 Provider 冒烟测试；
- 加固陈旧状态、取消、恢复、隐私和资源边界；
- 提交用户最终审查。

验收：

1. 初始模糊提示不会触发建模工具。
2. Agent 经过多轮询问和 RequirementReview 获得完整需求。
3. 几何、网格和求解分别只在对应 GUI 确认后执行。
4. 作用域和定义自动应用且可撤销。
5. 全部 Agent 名称遵守 `{type}-{function}`。
6. 模型预检通过。
7. 求解成功并能读取指定结果。
8. GUI 草稿期间不刷新，接受后按边界刷新。
9. 完整节点、单元和结果数组不进入 Provider payload。
10. 文档切换、revision 冲突、取消、网格失败和求解失败均有确定终态。
11. 保存、关闭、重开后已接受模型仍可重新网格和求解。
12. 现有 V0 `.inp` Agent 和 GUI 工作流继续通过。

## 25. 各阶段实施规则

每个 A 阶段必须：

1. 先编写独立实现计划。
2. 明确允许项、禁止项和目标文件。
3. 使用 Fake Provider 或直接 DTO 测试确定性控制流。
4. 将真实 Gmsh 和求解测试与纯契约测试分开。
5. 覆盖成功、拒绝、陈旧、取消和异常路径。
6. 不修改 README，除非用户另行要求。
7. 不在同一补丁中提前实现下一阶段能力。
8. 提交用户审查后再进入下一阶段。

任何阶段都不得放宽第 4、5、6、7、15、16、18、19、20 和 21 节定义的边界。

## 26. 当前路线之外

以下能力不属于 A0–A8 首个里程碑：

- imported `.inp` 到 native CAD 的逆向转换；
- 任意代码或脚本执行；
- 从图片自动恢复精确 CAD；
- 通用参数化约束求解器；
- 接触、材料非线性、几何非线性和动力分析；
- 自动工程规范认证；
- 自动网格收敛结论；
- 自动修改用户已有复杂多部件模型；
- 自动删除或覆盖已有结果；
- 任意 Gmsh 算法选择；
- 并行 Gmsh session；
- 完整 GUI 全局 undo/redo 栈；
- 未经用户授权的文件导出或工作区写入。

这些能力需要独立需求、边界、确认策略和验收计划。
